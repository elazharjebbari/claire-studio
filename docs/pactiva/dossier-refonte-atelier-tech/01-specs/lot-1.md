# Lot 1 · Cadre dock unifié + plancher de lecture

**Estimation** : L — périmètre large et transverse (la décision design le classe Effort L). Touche le contenant de TOUT le flux : refonte d'un composant central contrôlé (ResizablePanels) + 3 primitives nouvelles (CollapseRail, WorkspaceContextBanner, AuxDrawer) + helper pur + extension front ET backend de la persistance par compte + migration localStorage→serveur. Coût dominé par la QA non-régression (drag/clavier/ARIA, replis, overlays, fusion bandeaux, sync serveur multi-poste) et la préservation stricte des nombreux data-testid alimentant des e2e existants. Les sous-tâches sont bien isolables (backend, schéma, store, helper, primitives, câblage) ce qui borne le risque, mais le volume reste un L franc. · **Dépendances** : Lot 0 (Verrouillage du langage couleur) — REQUIS avant : ce lot tokenise les bandeaux d'état (suppression des amber/slate/sky en dur) et s'appuie sur la garde anti-hex + les tokens sémantiques warning/info/accent validés AA clair/sombre. La garde n'existe pas encore dans le repo actuel (.eslintrc.json sans règle hex, script check-no-hex.mjs absent) → livrer Lot 0 (au moins sa garde + tokens) d'abord., Réutilise (déjà en place, pas à recréer) : la couche prefs PAR COMPTE (store/prefs.ts, schema.ts, useUiPrefsSync, PATCH /me), la primitive Disclosure et les conventions de rail/repli existantes dans ResizablePanels, lucide-react., AUCUNE dépendance aux lots 2-9 : Lot 1 est l'infrastructure ; les presets de phase (greffe ultérieure) et le registre de raccourcis (Lot 9) viendront au-dessus sans bloquer ce lot.

## Objectif technique

Refondre le contenant 3 colonnes du workspace en un « dock » cohérent qui : (1) garantit une largeur-plancher au document central (clamp ~70ch, jamais sous le seuil lisible) ; (2) rend plan ET inspecteur repliables en rails symétriques w-8 (le repli gauche manque aujourd'hui) ; (3) fait passer Commentaires/Historique/Triage de frères flex compresseurs à des drawers overlay à droite qui ne descendent jamais le cœur de lecture sous son plancher ; (4) fusionne les 3 bandeaux empilés (session / verrou / vue-juge) en UNE bande contextuelle hiérarchisée (priorité verrou > vue-juge > session) tokenisée ; (5) remonte la persistance du layout (largeurs + replis) du localStorage par poste vers les prefs PAR COMPTE (serveur), avec cache local anti-flash et indicateur « synchronisé » ; (6) affiche un état « colonne au minimum » (poignée surlignée). Zéro hex, WCAG AA en clair ET sombre, séparateurs ARIA existants préservés, tous les data-testid conservés.

## Risques & pièges

- Régression de persistance multi-poste : migration localStorage(claire.workspace.layout) → prefs serveur. Risque que d'anciennes largeurs locales soient perdues ou en conflit. Mitigation : au 1er montage, si prefs.layout absent côté serveur mais cache localStorage 'claire.workspace.layout' présent, le lire UNE fois comme valeur initiale (one-shot migration) puis ne plus jamais l'écrire ; ensuite le compte fait foi.
- Whitelist backend OUBLIÉE : si on ajoute layout côté front sans toucher ui_prefs.py, le PATCH /me renvoie un blob SANS layout → le front croit avoir sauvegardé mais applyServer écrase avec le défaut au prochain /me (perte silencieuse + éventuelle boucle de re-PATCH). Le changement backend est OBLIGATOIRE et doit être testé (pytest sur merge_ui_preferences).
- Plancher trop agressif sur petits écrans : si containerWidth < left+CENTER_MIN+right, le calcul peut produire des largeurs négatives. readingFloor.ts doit dégrader gracieusement (replier d'abord les colonnes ou réduire proportionnellement) sans casser le layout — tester le cas écran étroit.
- Drawers overlay masquant le document : un AuxDrawer absolute peut recouvrir le texte. Mitigation : largeur de drawer bornée + le centre conserve son plancher visible ; voile léger token, pas de plein écran. Empilement de 2-3 drawers à borner (côte-à-côte ou plus récent au-dessus avec fermeture Échap).
- Perte de data-testid → casse des e2e/vitest existants : lock-banner, session-banner, judge-view-banner, lock-banner-unlock, comments/history/triage-* DOIVENT rester posés (la fusion des bandeaux ne doit pas supprimer ces ids, juste n'en afficher qu'un selon l'état). Risque de casser comments.spec/lock.spec/triage.spec si négligé.
- Dépendance Lot 0 non livrée dans le repo actuel : .eslintrc.json n'a pas encore la règle anti-hex et le script check-no-hex.mjs est absent. Tokeniser les bandeaux SANS la garde laisse le risque de réintroduction d'hex ; livrer Lot 0 d'abord (ou au minimum sa garde) pour verrouiller le gain.
- Boucle de synchro prefs : setLayout pendant le drag ne doit bump rev qu'au mouseup/keyup (pas à chaque mousemove) sinon flood de PATCH /me. Respecter la garde rev (mutateur idempotent) et débouncer côté geste, pas seulement côté réseau.
- ARIA des séparateurs : aria-valuemax dépend désormais du plancher central dynamique ; recalculer correctement (max = containerWidth - autres colonnes - CENTER_MIN) pour ne pas annoncer une plage fausse au lecteur d'écran.
