## Objectif technique

Faire de &lt;Button&gt; (aujourd'hui dans frontend/src/components/ui/primitives.tsx) l'unique source de vérité pour TOUTE la grammaire d'états : repos / hover / actif-pressé / désactivé / chargement / succès / erreur. Concrètement : (1) étendre l'API du composant avec les variantes sémantiques `danger` et `success` (mappées sur les tokens --sem-danger / --sem-success déjà déclarés en globals.css et exposés en Tailwind bg-success/text-danger/border-warning), une prop `isLoading` (injecte Loader2 lucide animé + aria-busy + disabled auto, largeur stable anti-saut de layout), une prop transitoire `tone: 'success'|'error'` (icône CheckCircle/AlertCircle ~1.2-1.5 s puis fade, role=status), des slots `leftIcon`/`rightIcon` à tailles normées (14px, currentColor) et des tailles `sm`/`md` ; (2) supporter l'état pressé via aria-pressed/aria-expanded reflété visuellement (anneau/fond plein), pour combler le trou des toggles « Annoter » et prefill ; (3) MIGRER tous les boutons ad hoc d'atelier vers &lt;Button&gt; — SelectionToolbar/BlockToolbar, QuickActionRail, prefill-switch et auto-prefill de WorkspaceToolbar — en supprimant les hover/disabled/focus redéfinis à la main ET tout hex/Tailwind brut d'état (emerald-*/amber-*/red-*) ; (4) câbler le pending réel : le bouton Soumettre passe isLoading pendant le flush (saveState/FlushResult déjà exposés par le store autosave), et SubmissionProgressDialog est tokenisé (red-400→danger, emerald→success, accent conservé). Aucun glyphe Unicode porteur de sens ne subsiste (✓ ＋ − ● ◐ ⧉ ◑ ⚖ remplacés par Lucide). Contrat : zéro hex, tokens sémantiques uniquement, frontière token MÉTIER (theme/triage/juge) ≠ token d'ÉTAT respectée, a11y AA clair+sombre, data-testid existants préservés.

## Store / données / types

- AUCUN nouveau store ni nouveau type Zustand à créer : l'état d'enregistrement est déjà porté par frontend/src/store/autosave.ts (useAutosaveStore : saveState 'idle'|'saving'|'saved'|'offline'|'retrying'|'error'|'unauthorized', lastSavedAt, manualRetry, flush(): Promise<FlushResult{converged,state}>).
- Le câblage pending se fait par LECTURE de saveState/flush dans WorkspaceToolbar (déjà fait : flushAutosave = useAutosaveStore(s=>s.flush), submitting local) — aucune mutation de schéma de store.
- L'état transitoire success/error du Button (`tone`) est un état LOCAL de composant (useState + timer ~1.2-1.5s), PAS du store global : il ne doit pas polluer le store workspace (réservé à l'interaction temps réel) ni le store prefs (réservé aux préférences par compte).
- Optionnel (mapping de confort, pas une donnée) : helper pur saveStateToButton(saveState) → { isLoading, tone, variant } pour dériver l'apparence du bouton Soumettre depuis saveState ('error'/'unauthorized'→tone 'error', 'saving'/'retrying'→isLoading), à placer en lib pure et tester isolément.

## Risques & pièges

- Régression visuelle large : la migration touche ~25 boutons sur 5 fichiers ; un changement de padding/taille du nouveau &lt;Button size='sm'&gt; peut casser l'alignement des barres flottantes (SelectionToolbar bottom-6, QuickActionRail 18x18px très contraint). Mitiger en calibrant size='sm' sur les dimensions actuelles (px-2 py-1) et en gardant le rail à h/w fixes.
- Casse de tests par assertion de classe : certains tests pourraient (à l'avenir) asserter des classes brutes ; aujourd'hui ils s'appuient sur data-testid/comportement — NE PAS renommer ni retirer un data-testid (selection-validate, block-validate, quick-validate-*, submit-btn, submission-*, prefill-*, autoprefill-toggle).
- Frontière métier≠état : tentation de router la couleur triage (QuickActionRail meta.color) ou le vert de thème via les tokens d'état success — INTERDIT. Le bouton triage garde sa couleur MÉTIER (--triage-*), seul l'état du système (valider/erreur/pending) utilise --sem-*. Vérifié en revue + garde de test.
- Prérequis Lot 0 non livré : la garde anti-hex (scripts/check-no-hex.mjs) et l'eslint token-only annoncés N'EXISTENT PAS encore dans le repo. Sans eux, des emerald-*/red-* peuvent réapparaître. Dépendance dure (voir dependances).
- Sur-configuration de l'API Button (variant + isLoading + tone + leftIcon/rightIcon + size + pressed) : risque d'incohérence d'usage. Mitiger par défauts sûrs + JSDoc + le helper saveStateToButton pour le cas Soumettre.
- isLoading + largeur instable : injecter le spinner sans réserver la largeur fait sauter le layout des barres. Réserver l'espace (min-width ou icône en overlay sur le label).
- prefers-reduced-motion : le spinner animate-spin doit porter motion-reduce:animate-none (déjà la convention dans SubmissionProgressDialog) — ne pas l'oublier sur le nouveau Button.
- Double vérité résiduelle : StatusPill, ClauseChip et l'overlay injustice portent d'autres hex d'état/métier ; ce lot ne tokenise QUE l'état des boutons + StatusPill — ne pas déborder sur le périmètre des autres lots (ClauseChip = lot iconographie ; injustice = lot fantômes).
- Toggle 'Annoter' : ajouter un état pressed visible ne doit pas changer la sémantique aria-expanded (palette ouverte) en aria-pressed — garder la sémantique d'origine (expanded pour la palette).
