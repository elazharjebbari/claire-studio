M réaliste : ~2–3 jours dev + tests, sans dépendance bloquante. · **Dépendances** : AUCUNE dépendance entrante : Lot 0 est le PRÉREQUIS transverse de tous les autres lots de la refonte atelier (couleurs/contraste = socle). ## Objectif technique

Transformer le langage couleur de l'atelier en propriété TESTÉE et non plus déclarée : (1) éradiquer les fuites d'hex en dur et de classes Tailwind brutes (emerald/amber/red/slate-XXX) dans les surfaces de l'atelier en les remappant sur les tokens sémantiques d'ÉTAT (--sem-success/-warning/-danger/-info) et sur des tokens MÉTIER tokenisés (thèmes déjà OK, niveaux de triage C1–C5 à tokeniser) ; (2) formaliser et garder la frontière « token métier ≠ token d'état » ; (3) compléter <Button> (variants danger/success, tailles sm/lg, slot icône + spinner loading) pour tuer le style ad hoc qui réintroduit des couleurs en dur sur les actions critiques ; (4) brancher une GARDE CI à deux étages : un linter anti-hex/anti-couleur-brute (check-no-hex.mjs + règle eslint) et un harnais Vitest qui prouve le ratio WCAG AA de chaque paire fond/texte (20 thèmes + certitude + 5 niveaux triage + 4 sémantiques) sur clair ET sombre via la luminance déjà présente dans tokens.ts. Périmètre = SOCLE atelier + primitives partagées ; on ne repeint PAS les pages admin/auth/public hors atelier (lot ultérieur), mais on les inscrit sur l'allow-list/TODO du linter pour éviter un mur rouge.

## Risques & pièges

- Régression visuelle subtile : remplacer `${meta.color}22` (hex+alpha sur 8 chiffres) par `rgb(var(--triage-cX) / 0.13)` change légèrement l'alpha effectif (0x22=0.133). Caler l'opacité à l'identique (0x22→0.133, 0x1a→0.10, 0x26→0.15) pour éviter tout écart perceptible.
- Casser un test asservi à un hex précis : peu de tests le font (boxShadow.toContain('inset') et colorClass.toContain('amber') sont les seuls repérés). MUST adapter validationDisplay.test.ts ; garder le mot 'inset' dans ClauseChip pour ne pas toucher clauseChip.test.tsx.
- Frontière métier/état mal appliquée sur le mode Compare : tentation de mapper agree→success / diverge→warning. C'est un PIÈGE (la convention interdit de recycler un token d'état comme signal métier). Trancher en revue : rampe compare MÉTIER dédiée par défaut. Ne PAS réutiliser --sem-* pour agree/diverge.
- Mur rouge du linter : 147 occurrences de couleurs Tailwind brutes dans le repo, majoritairement hors atelier (admin/auth/public). Si le linter scanne tout src/**, la CI explose. Limiter le périmètre dur à components/workspace/** + components/ui/** + lib/triage|validationDisplay, et mettre le reste en warning/TODO documenté.
- AA en clair non garanti pour certaines teintes triage : #84CC16 (lime C2) et #F59E0B (ambre C4) ont un faible contraste sur fond clair en texte plein. Le badge utilise le hex en couleur de TEXTE (color: meta.color) sur fond pâle — risque d'échec AA en clair. Solution : assombrir les variantes light de la rampe triage dans design-tokens.json (comme les sémantiques) jusqu'à passer le harnais.
- Glyphes Unicode→Lucide dans SentenceMenu : changer ✕/✓/◷/🌐 en icônes peut décaler l'alignement/aria-label. Conserver les aria-label existants et tailles 14px ; vérifier que les boutons restent focusables et que aria-pressed est préservé.
- Le champ `icon` de TRIAGE_LEVEL_META reste Unicode (●◐⧉◑⚖) : ne PAS le migrer en Lucide dans ce lot (relève de l'iconographie/menu) pour limiter le scope — mais le linter ne doit pas le flaguer (ce n'est pas une couleur).
- Double source de vérité résiduelle : tant que TRIAGE_LEVEL_META garde le hex en plus de tokenVar, un dev peut réutiliser le hex. Garder le hex UNIQUEMENT comme repli documenté et router 100% des usages UI sur tokenVar ; le linter attrape les usages directs de meta.color en style.
